# Modern Data Lakehouse: NYC Taxi Pipelines 🚖

Проект представляет собой готовую **end-to-end платформу данных (Data Lakehouse)** на базе архитектуры **Medallion (Bronze -> Silver -> Gold)**. Платформа собирает, очищает, валидирует и агрегирует сырые данные о поездках на такси в Нью-Йорке.

В основе стека лежит использование формата **Apache Iceberg**, который развернут поверх S3-совместимого хранилища и управляется через REST Catalog. Расчеты производятся с помощью распределенного движка **Apache Spark**, трансформация и контроль качества — через **dbt**, а координация всех процессов автоматизирована в **Apache Airflow**.

---

## 🏗️ Архитектура и Движение Данных

Данные проходят три классических слоя архитектуры Medallion:
1. **Bronze**: Сырые неизменяемые данные (паркеты поездок и справочники зон), загружаемые в объектное хранилище.
2. **Silver**: Очищенные структурированные данные. На этом этапе применяются строгие контракты (`contract: enforced: true`), проверяются типы данных и бизнес-валидация (количество пассажиров, корректность дистанции). Таблицы оптимизируются встроенной сортировкой Iceberg (`hierarchical sort`).
3. **Gold**: Бизнес-витрина (`gold_hourly_zone_metrics`), агрегирующая метрики поездок (выручка, средняя дистанция, чаевые) в разрезе часов и районов Нью-Йорка для BI-анализа.

---

## 🛠️ Стек технологий

* **Оркестрация:** Apache Airflow 3.3.0 (Slim-образ, LocalExecutor) + Astronomer Cosmos
* **Вычисления и Процессинг:** Apache Spark 4.1.3 (Spark Connect Server + Cluster)
* **Формат хранения данных:** Apache Iceberg 1.11.0 (REST Catalog)
* **Трансформация и Тестирование:** dbt-core + dbt-spark
* **Распределенный SQL-движок:** Trino 483 (для аналитических запросов)
* **Объектное хранилище (S3):** MinIO + MinIO Client (`mc`)
* **Системная БД:** PostgreSQL 16 (хранение метаданных Airflow, iceberg catalog и инициализация юзеров)
* **Развертывание:** Docker + Docker Compose

## ⚙️ Локальный запуск

### 1. Предварительные требования
Убедитесь, что у вас установлены **Docker** и **Docker Compose**. Проекту требуется хороший запас ресурсов (рекомендуется выделить Docker не менее **4-6 CPU** и **8-10 GB RAM** из-за тяжеловесных контейнеров Spark и Trino).

### 2. Важное примечание по переменным окружения (`.env`)
> ⚠️ **Безопасность на проде:** В данном репозитории все `.env` файлы в папке `./env/` намеренно **оставлены открытыми для удобства локального развертывания и проверки** проекта. В реальных условиях эксплуатации и продакшн-средах эти файлы были бы занесены в `.gitignore`, а вместо них использовались бы только безопасные шаблоны `.env.template`.

### 3. Запуск инфраструктуры
Выполните команду в корне проекта:
```bash
docker compose up --build -d
```

При первом запуске Docker Compose автоматически:
* Инициализирует базы данных в PostgreSQL (`init_dbs.sh`).
* Дождется старта MinIO, создаст бакет `warehouse` и сделает его публичным (`init_minio.sh`).
* Подтянет нужные `.jar` пакеты AWS SDK и Iceberg Runtime внутрь контейнеров Spark.
* Установит все dbt-зависимости (пакет `dbt_utils`) внутри изолированного окружения Airflow.

## 🔌 Настройка Airflow Соединений

После успешного запуска веб-интерфейс Airflow будет доступен по адресу: **`http://localhost:18080`** (Данные для входа по умолчанию: логин `admin` / пароль `password`).

Для корректной работы DAG-а `nyc_tlc` необходимо зайти в админ-панель Airflow (`Admin -> Connections`) и настроить **3 соединения**:

1. **`nyc-gov`** (Скачивание датасетов):
   * **Connection Type:** `HTTP`
   * **Host:** `https://cloudfront.net`
2. **`spark-local`** (Для задач PySpark и dbt-трансформаций):
   * **Connection Type:** `Spark Connect`
   * **Host:** `spark-connect`
   * **Port:** `15002`
